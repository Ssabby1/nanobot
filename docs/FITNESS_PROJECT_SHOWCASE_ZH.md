# Fitness Agent 项目展示

## 项目定位

这个子项目把 `nanobot` 的通用 agent 能力收口到一个垂直健身场景里，目标不是做开放式闲聊，而是做一个可执行、可追踪、可评测的训练与饮食助手。

当前已经覆盖的主链路：

- 用户建档与更新
- 周计划生成与查看
- 每日打卡与查看
- 基于近期反馈的调整建议
- 规则优先、LLM 兜底的结构化路由
- 多轮补槽、最近活跃用户复用、连续追问语气

## 项目亮点

### 1. 规则优先，LLM 兜底

路由层不是直接把用户请求交给模型自由发挥，而是先走规则路由；只有在规则不稳定、表达更自然、或需要更强语义理解时，才升级到 LLM 路由。

最终执行仍然统一落到 `FitnessService`，这样可以把“理解”和“执行”拆开，降低不可控性。

### 2. 多轮补槽和状态续填

当用户第一次没有把资料说完整时，系统会把 pending state 存下来。用户下一句只需要补缺失信息，不需要把整段重说一遍。

现在这套续填不仅能工作，而且会根据轮次切换说法：

- 首轮追问：更像 onboarding
- 第二轮追问：更像“接着补完”
- 休息日打卡：会切换成休息日语境

### 3. 内置评测集和自动评测命令

仓库里已经内置一套 deterministic 评测集，覆盖：

- 完整自然语言建档
- 多轮补槽建档
- 最近活跃用户复用
- 建档后生成周计划
- 休息日打卡补槽
- 打卡后生成调整建议

可以直接运行：

```powershell
nanobot fitness eval
```

评测结果会输出到工作区下的 `fitness_eval_reports/.../fitness_eval_report.json`。

## 推荐演示链路

### 演示 1：自然语言建档

```powershell
nanobot agent -m "我叫彭于晏，男，23岁，176cm，体重140斤，目标减脂，训练老手，已经锻炼五年了，每周练4次，每次60分钟，健身房训练，每天自己在家做饭吃"
```

### 演示 2：多轮补槽

```powershell
nanobot agent -m "我叫sasa，男，23岁，176cm"
nanobot agent -m "体重140斤"
nanobot agent -m "目标减脂，练了五年，每周练4次，每次60分钟，健身房训练，自己做饭"
```

### 演示 3：休息日打卡与续填

```powershell
nanobot agent -m "我今天没练"
nanobot agent -m "有点累，饮食还行"
```

### 演示 4：闭环调整

```powershell
nanobot agent -m "我今天练了卧推和深蹲，完成度80%，有点累，饮食还行"
nanobot agent -m "给我调整一下这周计划"
```

## 简历表述方向

如果把这个项目写进简历，建议重点强调下面这些关键词：

- 垂直场景 agent
- 规则路由 + LLM 兜底
- 结构化 action / arguments
- 多轮补槽与会话状态续填
- CLI 产品化入口
- 路由评测集与自动回归验证
